Playlists & Restore

Export Music.app playlists to a memory card, and repair missing tracks against your NAS index.

Export to memory card

Talks to Music.app live via AppleScript (osascript). Only user-created playlists (regular + smart) are listed — the built-in Library/Music sources and playlist folders are excluded.

Exportability check

A track is skipped, with the reason shown before you export, if:

  • it has no local file (e.g. an Apple Music match that was never downloaded)
  • Music.app reports it as protected AAC, or its extension is .m4p
  • the file can't actually be found on disk (NAS not mounted, etc.)

File layout

Each selected playlist becomes a folder at your chosen destination, containing its exportable tracks flat (no Artist/Album subfolders), named NN - Title.ext where NN is the track's position in the playlist — so most car head units play them in the intended order. Name collisions get a (2), (3), … suffix. Filenames are sanitized for exFAT/FAT32.

Restoring missing tracks

This is the one feature in the app that writes to your actual Music.app library, not just reads from it. Each playlist with missing tracks shows a Restore missing tracks button.

Match confidenceWhat happens
Exact Exactly one indexed file shares the missing track's title and artist (case/whitespace-insensitive) — imported into your Music library and swapped into the playlist automatically, no confirmation asked.
Ambiguous 2+ candidates, or only the title matched — left for you to review and pick via the UI, or skip.
No local match An automatic Music.app download attempt is made (for Apple Music-matched tracks never downloaded) — not guaranteed to work on every macOS/Music.app version.

The matching logic (src/playlistRestorer.js) deliberately has no fuzzy fallback — a false "ambiguous" is worse than a clean "no match," since "no match" is what triggers a download attempt instead.

Rebuild as an enriched copy

Right-click any playlist for a small options menu — its first two entries:

  • Rebuild as enriched copy — builds a brand-new playlist (named "Original Name (Enriched)", with a numbered suffix if that name is already taken) containing every track from the original, in the same order. Missing tracks with an exact local-index match are replaced with the real file, right in their original slot; anything ambiguous or unmatched is kept exactly as it was, still missing, still in the right position — nothing is ever silently dropped. The original playlist is never modified, so a rebuild is always safe to run, any time.
  • Delete playlist… — asks for confirmation, then deletes the playlist itself (not the tracks in your library). Irreversible from the app's side.

This exists specifically because in-place restore (above) can't fix track order — see the limitation below. Rebuilding a full ordered copy sidesteps it entirely: every track lands in its correct slot simply by the order the app calls Music.app's add/duplicate commands in, which is the one thing they reliably get right.

Known limitation (restore in place)

Restoring a track in place appends it to the end of the playlist, not back at its original position. This is a genuine platform limitation of Music.app's AppleScript dictionary — confirmed by directly testing its scripting interface: move only repositions whole playlists (not tracks within one), add's documented support for a location specifier (before/after/end of) doesn't actually work when called, and duplicate ... to before <track> runs without error but silently doesn't reposition anything either. There is no supported way to insert or move a track to a specific index within a Music.app playlist via AppleScript — which is why "Rebuild as enriched copy" above exists as a separate feature: it fixes order by building a new playlist from scratch instead of trying to reposition anything in the old one.

Practical effect if you still use in-place restore: since export numbers files by the playlist's current position in Music.app, a playlist exported after a restore run will have restored tracks trailing at the end, not in their original listening order. If exact order matters for a given playlist, manually drag the restored tracks back into place in Music.app before exporting.
