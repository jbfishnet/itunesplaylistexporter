Native macOS App

A native macOS app with a Dock icon, menu-bar item, native notifications, and a Swift + WKWebView interface.

What it is

macapp/main.swift is a thin native window: a plain WKWebView with no browser chrome, pointed at the same local Express server everything else runs on. Opening it starts server.js automatically if it isn't already running. Closing the window hides it while the app and its menu-bar item continue running; choose Quit Playlist Exporter in the menu-bar menu or press Cmd+Q to exit.

Build and install it:

cd macapp
./build.sh
cp -R "dist/Playlist Exporter.app" /Applications/

Menu bar

AppKit builds no menu bar at all without a storyboard/nib — early versions of this app had none, meaning no Cmd+Q, no Cmd+W, no Cmd+C/Cmd+V in the web UI's text fields. It now has a real App menu (About/Hide/Quit), Edit menu (Cut/Copy/Paste/Select All), and Window menu (Minimize/Zoom/Close), built in code in buildMainMenu().

Redistributable, not tied to one machine

The app used to hard-code this developer's own repo checkout path and Homebrew Node path — it only ever worked on the machine it was built on. It's now fully self-contained:

  • build.sh copies server.js, src/, public/, and a clean production node_modules directly into Contents/Resources/app — the .app carries its own server instead of pointing at a git checkout.
  • Node.js is located at launch (common install paths, then the user's shell PATH) instead of a hard-coded path. If none is found, an alert explains that and links to nodejs.org rather than failing silently.
  • The search index and logs live under ~/Library/Application Support/Playlist Exporter and ~/Library/Logs/Playlist Exporter — the app bundle itself isn't writable once installed.

Menu-bar app and autostart

The status-bar icon menu opens or quits the app. Closing the main window keeps the app running in the menu bar, where it can continue to deliver notifications. The Notifications tab lets you choose which export, library scan, and playlist events produce native macOS notifications and request notification permission.

macapp/install-autostart.sh installs a LaunchAgent that starts the app in menu-bar-only mode at login; uninstall-autostart.sh removes it. The app starts the bundled local server itself, and the window stays hidden until you choose Open Playlist Exporter from the status-bar menu.

Known limitation

The app is only ad-hoc signed — no Apple Developer account. Gatekeeper blocks ad-hoc-signed apps downloaded from the internet on any Mac other than the one that built them ("app is damaged and can't be opened"), until the person opening it either right-clicks it and chooses Open the first time, or runs xattr -cr "/Applications/Playlist Exporter.app" once after copying it over. Removing that friction for real requires enrolling in the Apple Developer Program (paid) and notarizing each build — not set up here, since it's a cost/account decision rather than a code one.

Versioning

package.json's version field is the single source of truth — nowhere else hard-codes a version number. It appears in the UI, bundle metadata, and build artifact:

  • The web UI, next to the app name, fetched live from GET /api/app-info.
  • The native app's Info.plist (CFBundleVersion/CFBundleShortVersionString) — About Playlist Exporter and Finder's Get Info show it for free.
  • The CI build artifact's name (Playlist Exporter-vX.Y.Z).
  • The in-app Release Notes tab displays the maintained release history and each build's generated UTC timestamp.
